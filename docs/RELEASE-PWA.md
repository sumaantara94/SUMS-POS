# PWA and live workspace synchronization

POS uses a fixed 100dvh application shell with persistent navigation/header and basket total; only inner content scrolls. Android installation uses the web app manifest, 192/512 PNG icons and standalone/fullscreen display preferences. Install button uses the browser prompt where available and otherwise explains Chrome's Add to home screen. Fullscreen requires a tap and browser support. POS touch gestures/viewport limit pinch/double-tap zoom; browser/accessibility settings can override it. Back Office/auth keep normal zoom. No native APK, Android kiosk/device lockdown or Bluetooth bridge is added.

Service worker caches only allowlisted public static shell assets. Cross-origin Supabase/auth requests and runtime business data are never cached. Offline shell can open, but transactions require internet; offline mutations are blocked and not silently queued. Build fingerprints shell files to version caches; a waiting update activates after old app windows close. Fonts fall back to system fonts offline. Install/gesture/device acceptance is not yet verified.

Migration 017/018 creates a tenant-read-only invalidation feed, one small event per workspace per database transaction; no order, payment or photo payload is replicated. Feed retains about 200 signals/workspace. Subscribers authenticate using the current Auth JWT, subscribe only to their workspace filter, and refresh records via the existing RLS APIs. Phoenix v1 protocol client handles join IDs, heartbeat/token renewal, reconnect backoff and closure on workspace change/logout. Feed status is visible. Updates debounce and avoid disrupting open dialogs/inputs; a 60-second recovery refresh and foreground/reconnect refresh recover missed signals. No changes were made to the SUMS Studio project or paid plan.

Validation: 24 Node tests; rolled-back database tests for event deduplication, tenant isolation, anonymous/direct write denial and replication publication; live WebSocket verification with two authenticated clients receiving one committed workspace event and a different workspace client receiving none. Temporary verification users/workspaces are removed. Browser Android installation, multi-device UI rendering and fullscreen are still unverified.

Hosting remains owner-private pending explicit public-audience permission. To allow staff without ChatGPT accounts, the static login shell must be accessible publicly; business APIs still require POS login and workspace membership. Never expose service keys. Sites access changes require an explicit new audience selection; installation alone does not change audience.
