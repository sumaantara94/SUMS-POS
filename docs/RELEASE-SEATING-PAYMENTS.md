# Seating, reservations and payment methods

Online POS now includes Meja & reservasi and cashier Laporan penjualan. Open bills show red with start time and elapsed minutes; reservations show orange. Waiter cannot select occupied/reserved tables. Server table locks also enforce the same rule at submission; stale client displays cannot bypass it. Table status uses a separate open-order query to avoid overlooking old open bills outside the latest 1000 history records. Cancellation or complete payment releases occupancy. Partial receipts are not posted: split must settle the whole bill atomically.

Cashier/owner reserves a free active table with guest and optional arrival time. Reservation stays blocked until cashier/owner uses Tamu datang / lepas. No automatic reservation expiry or scheduled multi-slot reservation calendar. Waiter can see reservations but cannot create/release them. Database membership checks keep data workspace-scoped.

Payment methods are cash, credit card, debit card, QR/QRIS, bank transfer and other. “Split pembayaran” records up to 10 parts of one invoice, with exact total equality required. This is a split tender, not separate guest invoices, item-level bill splitting or partial deferred payment. A cash part stores allocated amount, tendered and change; noncash references are optional. Do not enter card numbers. Noncash payments are manually confirmed records: no terminal authorization, generated QR, gateway webhook or bank confirmation integration was added.

Back Office Tax & service accepts percentage rates with two decimals and a tax-on-service switch. Calculation order: menu subtotal minus discount → service → tax on net menu (optionally including service). Rates are snapshotted when an order is submitted; changing settings applies only to new orders. Existing orders from previous versions keep zero rates. Amounts round to nearest rupiah. These are configurable operational charges, not automatic jurisdiction-specific tax advice.

Cashier reports are enabled by current server membership role, including existing and newly created cashier accounts. Waiter remains excluded. Net menu revenue/HPP/gross profit exclude tax and service; the new payment report shows total collections, tax/service and applied amounts by method. Split contributes each part to its own method and counts split invoices separately. Payment CSV exports invoice, time, method, applied amount and optional reference. History reporting still has the existing 1000-order cap and device-local rolling periods.

Migration 012 retires cash-only v2 payment permissions and adds server-checked quote/v3 settlement. A retry of already-paid settlement creates no additional receipts. Underpayment or invalid split rolls back all payment rows and financial snapshots. Old browser tabs need a reload. Physical Bluetooth integration and browser/device acceptance are still unverified.

Validation: 18 Node tests; transactional Supabase tests for reservation authorization, waiter blocks, occupancy/reseat, immutable rates, discounted tax/service, atomic split and cash change, QR recording, report rights and tenant isolation. Existing transaction/restaurant regression tests use v3 settlement. Test fixtures roll back.
