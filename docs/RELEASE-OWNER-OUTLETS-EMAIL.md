# Owner navigation, outlets and daily sales email

Back Office has compact line icons, an outlet switcher, clean page headings, and profile access anchored at the lower left. Profile settings contain display name, device language and logout. The Open Online POS header button, connection banner, technical database badges and oversized empty approval panel are removed. Notifications are a bell/count and a compact bar when requests are pending; clicks open the approval popup.

Outlets can be added under the current business (up to 20 including the main outlet). Brand/category/fees/restaurant settings are inherited; products, stock, tables and staff start separate. Root owners receive outlet memberships. Other roles and staff retain only their assigned outlet access. The pre-existing additional-workspace upgrade guard remains enforced. Outlet creation does not purchase or upgrade a plan.

Reports → Email reports configures enabled daily sending, the authenticated owner's email, up to five explicitly supplied additional recipients and delivery time in outlet timezone. Defaults for the existing main outlet are enabled, 08:00 Asia/Makassar, owner only. Manual reports accept completed calendar days within one year. Recipient/date jobs are deduplicated and freeze their content; messages are sent individually so recipients are not disclosed to one another.

The database cron checks every five minutes. Only the scheduler can invoke the global private sender; owner queue calls are constrained to their selected outlet and cannot run it. Delivery uses a dedicated domain-scoped sending-only Resend key encrypted in Vault. The current sender uses the private synchronous HTTP adapter, keeping credentials out of the pg_net request queue. SQL snapshots calculate paid sales, fee/discount totals, recorded COGS and missing-cost count, completed refunds/net collections, cancellations/voids and payment-method totals in the outlet timezone. Email has HTML and plain-text versions.

Delivery retries transient failures up to three times within a 23-hour window with a stable provider idempotency key; permanent failures are logged. The POS sender is limited to 80 attempted jobs per UTC day to leave headroom under the shared account's observed Free limits (100 daily/3,000 monthly). These do not reserve capacity from other apps. No paid plan or automatic upgrade is enabled. Provider acceptance is logged as sent; delivery/bounce is a separate provider event.

Verification: 35 Node tests, syntax/static build and rollback-only database tests for outlet/tenant/staff separation, unchanged workspace gate, owner-only email settings, recipient deduplication, scoped queues and denied sender/Vault access. The first real report for 2026-10-12 reached the verified owner address; Resend reports delivered and the database log is sent. Test data does not persist. Browser/mobile visual verification remains unavailable.

Automatic review rejected an owner queue invoking the global worker; that operation was discarded. Manual delivery remains a scoped queue processed by the approved scheduler. It also rejected removal of the managed pg_net extension; removal was discarded and the unused extension remains. New delivery no longer writes credentials there.
